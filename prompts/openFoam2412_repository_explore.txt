### Significant directories
- **`src/`** — Core C++ libraries. Finite-volume framework, mesh primitives, turbulence/thermophysical/transport models, dynamic mesh, parallel decomposition, function objects. The bulk of the codebase.
- **`applications/`** — Source for executables. Two subtrees:
  - `solvers/` — physics solvers, grouped by continuum-mechanics category (`incompressible/`, `compressible/`, `multiphase/`, `combustion/`, `heatTransfer/`, `lagrangian/`, `stressAnalysis/`, `electromagnetics/`, `acoustic/`, `basic/`, `DNS/`, `discreteMethods/`, `financial/`, `finiteArea/`).
  - `utilities/` — pre/post-processing, mesh tools, parallel helpers, surface/thermophysical/miscellaneous CLI tools.
- **`bin/`** — User-facing shell scripts and wrappers (e.g. `foamJob`, `paraFoam`, `foamCleanTutorials`). Not compiled C++.
- **`etc/`** — Runtime configuration: `bashrc`/`cshrc` for environment setup, default `controlDict`, compiler/MPI presets. Also contains reference material worth knowing about for exploration:
  - `etc/caseDicts/annotated/` — annotated example dictionaries (`blockMeshDict`, `decomposeParDict`, `snappyHexMeshDict`, etc.) used as syntax/option references.
  - `etc/caseDicts/` (other subdirs) — reusable function-object dictionaries (`postProcessing/`, `solvers/`, `mesh/`, `surface/`, `profiling/`).
  - `etc/templates/` — full case templates (e.g. `inflowOutflow`, `closedVolume`, `axisymmetricJet`).
  - `etc/codeTemplates/` — boilerplate for `codeStream`/`codedFixedValue` and similar runtime-compiled snippets.
- **`tutorials/`** — Example cases (structure detailed below).
- **`wmake/`** — OpenFOAM's build system: compiler rules, link rules, helper scripts.
- **`modules/`, `plugins/`** — Optional add-on submodules/plugins; typically empty unless populated externally. Built via `Allwmake-modules` / `Allwmake-plugins`.
- **`Allwmake`** (+ `-modules`, `-plugins`) — Top-level build entry points.

### `tutorials/` path convention

General pattern:

```
tutorials/<case_domain>/<solver>/[<category>/]<case_name>/
```

- **`case_domain`** — physics class. Directories: `incompressible`, `compressible`, `multiphase`, `combustion`, `heatTransfer`, `lagrangian`, `stressAnalysis`, `electromagnetics`, `DNS`, `basic`, `financial`, `IO`, `finiteArea`, `discreteMethods`, `preProcessing`, `verificationAndValidation`, `modules`, and the special `mesh` (see below). A shared `resources/` directory and top-level `Allrun`/`Allclean`/`Alltest` scripts also live here.
- **`solver`** — the executable the case runs against (e.g. `simpleFoam`, `pimpleFoam`, `rhoCentralFoam`, `interFoam`, `chtMultiRegionFoam`).
- **`category`** *(optional, only where the solver supports multiple modeling approaches)* — most commonly the turbulence regime: `RAS/`, `LES/`, or `laminar/`. Many solvers omit this layer entirely.
- **`case_name`** — contains the actual tutorial case (standard `0/`, `constant/`, `system/` subfolders).

Example: `tutorials/incompressible/pimpleFoam/LES/pitzDailyMapped/`

### `tutorials/mesh/` is different

`tutorials/mesh/` does **not** follow the solver pattern. It is organized by **meshing application** — each subdirectory targets one mesh tool and demonstrates its concepts and dictionary syntax:

```
tutorials/mesh/<mesh_application>/<case_name>/
```

where `<mesh_application>` is a meshing executable (`blockMesh`, `snappyHexMesh`, `foamyHexMesh`, etc.) and `<case_name>` contains the actual tutorial case. Cases here are meshing references, not full physics simulations.
